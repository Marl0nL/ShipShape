{% if inv is none %}

New fleet recommended

FleetLedger creates every key it needs (its own login key for Ships and a small certificate authority) and looks after them: they are locked with passphrases only FleetLedger knows, kept in {{ 'your OS keyring' if keyring_usable else 'a private file' }}, and loaded into ssh-agent when needed. You never see, name or type them.

Your own SSH key: each Ship puts its public half on its agent user, so ssh, herdr --remote and ship-fleet ssh let you in. Its private half never leaves this computer. {% if your_keys %}Found in ~/.ssh.{% else %}None found in ~/.ssh.{% endif %}

With Tailscale, you reach your Ships from anywhere (a phone hotspot, say) with no ports opened on your router; SSH with each Ship's pinned key is still the only way in. FleetLedger makes each Ship a single-use key with an OAuth client that may do only that. You can do this later.

  1. In Access controls, add these pieces to your policy (or replace Tailscale's starter policy, which lets everything reach everything) and save.
    Show them
    {{ policy }}
    They let your own devices reach Ships on port 22, and nothing reach your devices from a Ship.
  2. In Trust credentials, make an OAuth client: Auth Keys, Write; tag tag:ship. Copy its client id and secret.
  3. Paste them here. FleetLedger checks the client signs in, can make tag:ship keys (which shows step 1 worked), and has the right scopes, before saving anything.

Kept in {{ 'your OS keyring' if keyring_usable else 'a file only you can read' }}. If you already put it in your keyring (service fleetledger, item tailscale-oauth:<client id>), leave this empty.
