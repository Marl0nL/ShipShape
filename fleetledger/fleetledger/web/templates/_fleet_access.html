Each Ship has a login for you, apart from the agent's: it has sudo, your key and your certificates, for admin work (ssh {{ inv.owner }}@<ship>). The agent's login keeps no sudo. Changing the name sets it on every Ship now, and on new ones.

Trusted machines

Each machine you attach from gets short-lived certificates, for the logins you choose here: the agent's (to attach to it, herdr --remote) and your own (sudo). A machine that should only attach to agents, a shared one say, needs only the agent's. Trust another: ship-fleet trust NAME --key its.pub --logins agent (or owner, or both). Machines trusted before your login had certificates of its own keep both. A Ship not updated yet still lets any of the agent's certificates log in as you: update every Ship before relying on "the agent only".

You look after these keys' passphrases. FleetLedger needs the admin key loaded in ssh-agent whenever it connects to a Ship; when it is not, you are asked for its passphrase{% if desktop_agent %}, in a desktop pop-up from your keyring, each time{% endif %}. Let FleetLedger look after them instead and you are not asked again: type each current passphrase once, and it re-encrypts the key file with a passphrase it keeps in {{ 'your OS keyring' if keyring_usable else 'a private file' }}. The keys themselves stay the same (Ships, certificates and trusted machines keep working); the old passphrase no longer opens the file. Nothing changes unless you tick the boxes.
